# 代码生成与构建

## 概述

系统可以将自然语言需求自动转化为完整的 Minecraft 插件项目，编译为 JAR 文件并提供下载。

## 流程

### 1. 需求分析

用户在对话页输入需求后，系统先提取核心类型和版本。如果用户没有明确说明，弹出选择面板补充。完成后生成结构化的开发步骤。

### 2. 项目规划（Planner）

点击「生成项目 & 构建 JAR」后，Planner 调用大模型分析需求，输出：

- **项目名称**（英文驼峰）
- **Java 版本**（根据 MC 版本自动推导：1.17+ → Java 17，1.13-1.16 → Java 11，≤1.12 → Java 8）
- **包名**（全小写）
- **文件树**（每个文件带路径、职责描述、生成顺序）

### 3. 逐文件生成

按 Planner 确定的顺序逐个生成源文件：

- 每次只传一个目标文件的路径和职责
- 已生成文件的摘要作为上下文传入下一次调用
- 模型只返回文件正文，不返回解释

UI 实时显示：每个文件的状态（⏳ 待生成 / 🔄 生成中 / ✅ 已完成），点击可预览代码。

### 4. 文件校验

验证 Planner 规划的所有文件是否都已成功生成。

### 5. 构建

生成的文件上传到 GitHub 仓库的临时分支，触发 GitHub Actions 执行 Maven 构建：

```
创建临时分支 → 上传文件 → 触发 workflow → 等待构建
```

UI 显示构建等待动画和日志。

### 6. 下载

构建成功后显示下载按钮，点击即可获取包含 JAR 的压缩包。下载完成后自动清理临时分支。

## 服务端 API

| 端点 | 方法 | 说明 |
|------|------|------|
| `/api/generate/plan` | POST | Planner 规划 |
| `/api/generate/file` | POST | 生成单个文件 |
| `/api/generate/verify` | POST | 校验文件完整性 |
| `/api/generate/build` | POST | 上传 + 触发构建 |
| `/api/generate/status` | GET | 轮询构建状态 |
| `/api/generate/download` | GET | 下载 JAR |

所有端点的任务状态通过 Cloudflare KV 持久化，TTL 1 小时。
